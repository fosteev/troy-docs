Inventory Redesign

Аудит того, что уже собрано в мобильном клиенте, и интерактивный прототип того, как инвентарь может выглядеть отдельным экраном. Копия в макетах — английская (как в redesign-prompt), заметки — по-русски. Кликабельно: фильтры, слоты, предметы, Equip/Unequip/Use.

AS-IS

Что сейчас есть в приложении

Hero pageодин длинный скролл, инвентарь в самом низу
  • Профиль, экипировка, атрибуты, derived-статы и мешок — один ListView. До мешка ~3 экрана скролла.
  • Папка features/inventory/ пустая (.gitkeep) — всё живёт в features/profile/.

Данные (domain)

  • InventoryItem: id (catalog Item.id), name, type, rarity, glyph, slot?, quantity, 9 бонусов (str/int/sta/agi/spi/armor/mResist/physDmg/magicDmg), description? (бэкенд пока не отдаёт)
  • HeroSnapshot: profile + items + equipped: Map<HeroSlot, itemId>; bag = всё, что не надето; capacity = 40 (константа на клиенте)
  • Слоты: head, body, weapon, shield, boots, ring (ring ↔ backend ACCESSORY)
  • Rarity 5 ступеней, цвета захардкожены в RarityColors
  • Фильтры: all / weapon / armor / accessory / consumable (accessory — по type, у бэкенда такого type нет)

Виджеты (presentation)

  • EquipmentPanel — 3 слота | анимированный спрайт класса | 3 слота; тап по заполненному слоту = unequip без подтверждения
  • EquipSlot — 58px, рамка цвета rarity + glow; пустой — dashed с названием слота
  • InventorySection — заголовок + «12 / 40 slots», чипы-фильтры, сетка 4 колонки (мин. 12 ячеек, добивка dashed), футер с золотом
  • ItemCell — glyph + бейдж количества; selected = толще рамка и ярче glow
  • ItemGlyphIcon — 11 пиксельных глифов на CustomPainter (sword, axe, hammer, shield, helmet, armor, boots, ring, gem, potion, scroll)
  • showItemInspectSheet — bottom sheet: иконка, имя (цвет rarity), «Rarity · Type ×N», описание, чипы бонусов, кнопка Equip (если есть slot)

Поведение (HeroCubit)

  • load → один снапшот GET /character/me
  • setFilter, toggleInspect / clearInspect (selectedItemId открывает sheet через BlocConsumer-listener)
  • equip(itemId), unequip(slot), allocate(attr) — без optimistic UI, ждём свежий снапшот с бэкенда
  • _mutationInFlight — защита от даблтапа, но UI никак не показывает «в полёте»
  • Ошибка → snackbar, снапшот не трогаем

Чего нет

  • Сравнения с надетым предметом (дельта статов)
  • Use для расходников, Discard — и на бэкенде тоже (gaps #2, #3)
  • Сортировки, пометки «новое», индикатора апгрейда
  • Skeleton при загрузке, состояния «запрос в полёте» (пустой мешок — просто dashed-сетка, это ок)
  • Equip из слота (слот → выбрать из подходящих)
  • Подтверждения при unequip; после equip — только новый снапшот, без «+7 ATK»-фидбэка (DoD MVP-3: «визуальная обратная связь после изменения статов»)
  • Стак экипируемых: «Rusty Blade ×3 (equipped)» — неопределённое поведение (gap #5)

PROTOTYPE

Инвентарь как отдельная вкладка · sharp pixel-frames по redesign-prompt

Каждый телефон — независимая копия состояния. Тап по предмету → карточка со сравнением; тап по слоту → что надето + чем заменить; чипы и сорт работают.

1 · Bagглавный экран инвентаря
  • Золото — в app bar, а не в футере: это валюта, ей место рядом с заголовком.
  • Кукла из 6 слотов сжата в одну полосу над мешком. Тап по слоту = фильтр «что подходит сюда» + карточка слота (экран 3). Полная кукла с анимированным спрайтом остаётся на вкладке Hero.
  • Вместимость — сегментированный бар, не текст. При ≥90% — оранжевый.
  • Ячейка: rarity-рамка (как сейчас) + метка слота внизу слева, NEW для свежего лута, ▲ если лучше надетого в свой слот (считается на клиенте: сумма бонусов). Количество — как сейчас.
  • Сорт: rarity ↓ / newest / type. Фильтр по слоту подсвечивает, а не прячет — контекст сохраняется.
  • Навбар: сейчас три таба (BACKPACK · MAP · MENU), и BACKPACK ведёт на Hero. Здесь BACKPACK → BAG (только мешок), а профиль/кукла/статы — отдельный HERO. Если четыре таба не хочется — HERO можно спрятать в MENU или в app bar мешка.
2 · Inspectкарточка предмета со сравнением
  • Те же данные, что в текущем sheet, но бонусы — строками, а не чипами: третья колонка — дельта против того, что сейчас в этом слоте (Iron Sword). Это и есть «обратная связь по статам» из DoD, только до нажатия.
  • Equip → sheet закрывается, тост «Equipped · PHYS DMG +7», предмет уезжает в куклу. Тост — обещание; реальные цифры пересчитает бэкенд.
  • Discard — пунктиром: эндпоинта нет (gap #3). Убрать пунктир, когда появится. Продажи в инвентаре нет — экономика не здесь.
  • Описание — из Item.description, которого ещё нет (gap #1). До него — не показывать блок вовсе, без «Lorem».
3 · Slotтап по надетому — снять или заменить
  • Сейчас тап по слоту = мгновенный unequip. Здесь — карточка: что надето, Unequip, и «Swap for» — только подходящие в этот слот, с ▲ у апгрейдов. Тап по кандидату = equip (бэкенд сам снимает старое).
  • Пустой слот → та же карточка без блока «Equipped», сразу список кандидатов. Убирает сценарий «скроллю мешок, ищу, что надеть на голову».
4 · Consumableрасходник — Use с количеством
  • Для type = consumable вместо Equip — Use со степпером (1…N). Эффект — строкой («Restores 50 HP»). Эндпоинт POST /inventory/use/:itemId и поля эффекта — gap #2; блокер — нет persistent HP между боями.
  • Если зелья режем из MVP-3 — фильтр consumable остаётся, кнопка Use уходит, sheet просто информационный.
5 · Emptyмешок пуст
  • Никакого «Your bag is empty» — просто пустая dashed-сетка, бар 3 / 40 и кукла с надетым. Пустой мешок ≠ голый герой.
  • Тот же каркас использовать под skeleton при загрузке: dashed ячейки + shimmer, без спиннера в центре.
