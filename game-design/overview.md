# Game Overview

## Концепция

Troy — мобильная геолокационная RPG. Игрок перемещается в реальном мире, на карте вокруг него появляются монстры. Чтобы вступить в бой, нужно физически подойти к точке на карте. Бой проходит в реальном времени с системой скиллов и кулдаунов. За победу — опыт и лут.

## Core Loop

```
1. Открыть приложение → карта с позицией игрока
2. Увидеть монстров в радиусе видимости
3. Физически подойти к монстру (геолокация)
4. Начать бой (реалтайм, скиллы + автоатака)
5. Победить → получить XP + лут
6. Уровень вырос → новые скиллы, очки атрибутов
7. Экипировать лут → стать сильнее
8. Повторить с более сильными монстрами
```

Убитый моб исчезает **только для убившего персонажа** (учёт по уникальному ID спавна
на персонаже); для других игроков он остаётся на карте. Мир мобов фиксирован на неделю
и **respawn'ится каждую среду в 00:00 UTC**: старый набор сносится, генерируется свежий
(по лимиту зоны на каждую соту-территорию), прогресс убийств обнуляется. Между средами карта
мобов не меняется.

## Устройство мира: город → зона → территория

- **Город** — граница мира. Обводится на карте в админке; снаружи мобов нет. У города одно
  геометрическое свойство кроме границы — ребро соты (100–5000 м).
- **Зона** — логическая единица без геометрии: название, тип (равнина, лес, горы, болото, город,
  руины), диапазон уровней, пул мобов, фон арены, лимит спаунов на соту в неделю. Зоны заводятся
  сидом и правятся в админке; одна зона может лежать в нескольких городах.
- **Территория** — сота гексагональной сетки, на которую разбит город. Единственное свойство —
  зона (или пусто: пустошь без мобов). Мобы спаунятся внутри территорий: `лимит зоны × число её сот`.
  Раскладку зон по сотам делает генератор (каждой зоне свой центр, сота уходит ближайшему), поверх —
  ручная кисть в админке.

Клиент видит только следствия: список зон рядом (`/map/zones`) и спауны (`/map/entities`).
Спека и прототип админки — `roadmap/cities/`.

## Основные сущности

### User (аккаунт)

Учётная запись игрока. Содержит:
- Email, пароль (хеш)
- JWT-авторизация
- Верификация email
- Список персонажей

### Character (персонаж)

Игровая сущность, привязанная к User. Содержит:
- Класс (Warrior / Mage)
- Уровень (1–30)
- Базовые атрибуты (Strength, Intelligence, Stamina, Agility, Spirit)
- Распределённые свободные очки
- Инвентарь и экипировка
- Классовый ресурс (Rage для Warrior, Mana для Mage) — HP и ресурсы инициализируются с максимума при каждом бою
- Позиция на карте (геолокация)

Один User может иметь несколько Character. На карте активен только один персонаж в каждый момент.

## Основные принципы дизайна

1. **Простота входа** — 2 класса, понятные механики, не перегружать новичка
2. **Глубина прокачки** — свободные очки атрибутов дают разные билды одного класса
3. **Физическое перемещение** — ходьба как основная механика, anti-cheat по скорости
4. **Честная боёвка** — результат боя зависит от уровня, шмота и умения использовать скиллы, а не от доната
5. **Расширяемость** — система атрибутов и скиллов позволяет добавлять новые классы без переделки ядра
