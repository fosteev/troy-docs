# MVP-0 — Current Flow Stabilization

Цель: закрыть текущий пользовательский путь от auth до карты без сломанных переходов, временных заглушек и визуального рассинхрона.

## Продуктовый результат

Пользователь после логина всегда попадает в корректное состояние:

- нет персонажей → создание персонажа;
- есть персонажи, активный выбран → карта;
- есть персонажи, активный не выбран → выбор персонажа;
- из профиля можно сменить активного персонажа.

## Backend

- Проверить, что `GET /characters` возвращает `isActive`.
- Проверить, что `POST /characters` делает созданного персонажа активным.
- Проверить, что `POST /characters/:id/select` снимает active flag с остальных персонажей пользователя.
- Ошибки должны возвращаться в едином API envelope.

## Flutter

- Закрыть текущий WIP выбора персонажа.
- После выбора персонажа не показывать пустой loading screen, а обновлять список и состояние выбранной карточки.
- Не давать выбирать уже активного персонажа.
- После создания персонажа вести пользователя на карту.
- Подключить map sprite для Mage.
- Маркер игрока на карте должен зависеть от класса активного персонажа.
- Убрать `flutter analyze` warning в router imports.
- Проверить back/logout behavior на экранах создания и выбора персонажа.

## Definition of Done

- `flutter analyze` проходит без issues.
- Новый пользователь создает персонажа и попадает на карту.
- Пользователь с несколькими персонажами выбирает активного и видит правильный sprite на карте.
- Повторный запуск приложения сохраняет auth state и active character flow.
