# Групповой бой — N×N (паки мобов → кооп)

> **Статус: идея зафиксирована (01.09), в работу не взята.** Порядок: не раньше закрытия
> MVP-3; этап 1 (паки) — кандидат сразу за MVP-4, этап 2 (кооп) — после MVP.

Переделка боёвки из жёсткого 1v1 в состояние «бой», куда входят X игроков и Y мобов
(модель WoW). Каждый участник — игрок или моб — выбирает себе цель и наносит урон ей.
Бой заканчивается, когда мертвы все игроки, мертвы все мобы, либо все живые игроки сбежали.

## Продуктовый результат

- На карте встречаются паки («стая волков»): один маркер, бой сразу против нескольких мобов.
- В бою — выбор цели тапом; каждый моб живёт своей жизнью: свои HP, интенты, касты, эффекты.
- (Этап 2) Несколько игроков входят в один бой и бьют пак вместе.

## Целевая модель сессии (фиксируем сразу, чтобы этап 1 не переделывать)

Сессия — не `{player, monster}` ([battle-session.md](../../technical/battle-session.md)),
а две стороны со списками участников:

- у каждого участника: `hp / ресурс / effects / cast / targetId`;
- игроки выбирают цель сами (тап по мобу), мобам цель назначает сервер
  (этап 1 — тривиально: единственный игрок; этап 2 — простая аггро-таблица по нанесённому урону);
- конец боя: все мобы `hp ≤ 0` → VICTORY · все игроки `hp ≤ 0` → DEFEAT ·
  все живые игроки завершили побег → ESCAPE. Побег индивидуален: сбежавший выходит
  из сессии, для остальных бой продолжается;
- текущий 1v1 — частный случай этой модели (1 участник с каждой стороны).

## Этапность

### Этап 1 — паки: 1 игрок × N мобов

Реализует «стаю волков». Социального слоя нет — вся ценность фичи и весь рефакторинг
модели без новых продуктовых вопросов.

- [ ] Контракт v2 в `battle-session.md`: `monsters: []` в снапшоте (id, hp, effects, cast),
      цель в `battle:action` / отдельное `battle:target { targetId }`, лог с `sourceId/targetId`
- [ ] TickEngine: цикл по участникам; у каждого моба независимые интенты/касты
- [ ] Spawn: состав пака в спавне (count / список мобов); маркер пака на карте —
      UI-бейдж «×3» поверх обычного маркера, генерация не нужна
- [ ] Награды: XP/лут агрегируются по паку; `CharacterKill` на каждого моба пака —
      персональная видимость работает как сейчас, без изменений
- [ ] UI (арена P4): раскладка N мобов, тап = смена цели, подсветка текущей цели,
      лента намерений per-моб
- [ ] Баланс: паковый коэффициент — моб в паке слабее соло-моба того же уровня
      (суммарный DPS пака ≈ 1.2–1.5× соло-моба, не N×)

### Этап 2 — кооп: M игроков × N мобов (после MVP)

Кода меньше (модель уже готова), продуктовых решений больше:

- [ ] Вход в бой: как игроки оказываются в одном бою (пати? вход в открытый бой рядом?)
- [ ] **Конфликт с персональной видимостью**: килл сейчас персональный (`CharacterKill`),
      совместный бой = совместный килл — решить, исчезает ли моб для всех участников
- [ ] Распределение XP/лута (поровну / по урону), защита от личеров
- [ ] Reconnect для N игроков; поведение боя при дисконнекте одного
- [ ] Скейл статов пака от числа игроков

## Ассеты: решение (зафиксировано 01.09)

Стаю **не** генерим единым спрайтом: анимации играли бы всей группой, смерть одного волка
не изобразить (нужны листы «×3/×2/×1» на каждую анимацию — комбинаторный взрыв), диффузия
не держит консистентными несколько субъектов между кадрами.

Правильно — **один спрайт-лист моба, N инстансов на клиенте**:

- рассинхрон стартового кадра idle (главное, чтобы не «дышали» синхронно), flip,
  scale 0.9–1.1, лёгкий tint;
- вожак (опционально) — отдельная генерация той же морды через референс
  (RD reference images), крупнее/темнее;
- новых обязательных ассетов нет.

## Оценка сложности

- **Этап 1** — умеренно-крупная: контракт + сессия/движок + UI боя + баланс,
  по объёму сопоставимо с `mvp-2/polish` целиком.
- **Этап 2** — крупная, и в основном за счёт продуктовых решений (социальный слой,
  видимость, лут), а не кода боя.
