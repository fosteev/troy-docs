# MVP-2 · Battle polish: отзывчивость и «живость» боя

Продолжение [MVP-2](../README.md). Каждая фаза — отдельный файл, ссылки в таблице статуса. Механика и транспорт готовы
(server-authoritative тик 250 мс, снапшоты `battle:state`, спрайты классов,
выпад/отдача/тряска/цифры урона на клиенте — коммит `troy-flutter 8f212e0`).
Бой при этом ощущается как «таблица с двумя картинками». Этот документ —
что именно не хватает и в каком порядке закрывать.

## Статус

- [x] [P0](./p0-event-contract.md) — Контракт событий боя (backend)
- [x] [P1](./p1-responsiveness.md) — Отзывчивость, читаемость, устойчивость
- [x] [P4](./p4-arena-layout.md) — Перекладка экрана в «Арену»
- [x] [P3](./p3-start-result-levelup.md) — Старт, результат, level-up
- [x] [P5](./p5-intent-feed.md) — Лента намерений моба
- [ ] [P2](./p2-audio-vfx-assets.md) — Звук, VFX, арена, спрайты мобов — код готов, ждёт ассетов

**Осталось по боёвке — всё в P2 и всё упирается в файлы:**

- [ ] SFX: удар физ/маг, крит, промах, каст-старт, стан,
      победа/поражение/побег, level-up, ambient арены (1 луп на зону).
      В клиенте нет ни пакета аудио, ни `assets/audio`.
- [ ] `BattleAudio` (пул, приглушение при системном mute) и хаптика на каст,
      стан, низкий HP — пишется после того, как появятся звуки.
- [ ] VFX-слой по `damageType` + партиклы крита — листов нет; `damageType`
      в presentation боёвки сейчас не читается вообще.
- [ ] Листы `Monster.spriteHit` / `Monster.spriteDeath` — клиент их уже
      играет, залить через админку.
- [ ] Фоны арен по зонам (`SpawnZone.arenaBackground`) — 3 шт. на московские
      зоны сида; без них берётся бандловая подложка.
- [ ] Иконки мобовых скиллов (5 шт., `MonsterSkill.iconUrl`) — поле и рендер
      есть, фолбэк рисует инициалы кода.

**Хвосты вне P2** (не блокируют фазу, живут отдельно):

- `MonsterSkill.name` нет — лента humanize'ит код. Колонку заводить, только
  если humanize перестанет читаться.
- Swagger `BattleStartResponseDto` описывает старый пораундовый ответ
  (`rounds`), `battle:end` в Swagger не описан вовсе (идёт только по WS) —
  TODO в `troy-backend/CLAUDE.md`.
- Баланс (3-й скилл классам, фаза «ярость» у моба) — это MVP-4, см. «Баланс»
  в конце файла.

## Диагноз (аудит 2026-08-29)

1. **Задержка реакции.** Тап → сервер → снапшот → анимация: 300–500 мс мёртвой
   паузы. Ack `battle:action {accepted, reason}` бэкенд отдаёт
   (`on_cooldown | no_resource | stunned | not_active`, `validateSkill` в
   battle.service), но клиент его выбрасывает — игрок не видит отказа.
2. **Контракт событий теряет данные.** `kind:'skill'` не несёт crit/miss
   (крит скиллом не трясёт экран, промах скиллом рисует «0»); `kind:'effect'`
   не несёт тип эффекта (клиент трактует `amount>0` как хил → SLOW от frost bolt
   рисует зелёный «+N» на монстре). Нет `target`, `damageType`, событий
   начала/прерывания каста, истечения эффекта.
3. **Движок не реализует SLOW / BUFF / ABSORB** (только DOT и STUN); SLOW у
   frost_bolt — только чип в UI. HEAL/BUFF/ABSORB применяются к `target` =
   противнику (латентно: в сиде таких скиллов нет).
4. **Всё сырыми кодами:** «Каст fireball…», чипы `SLOW 3s`, лут — UUID предмета,
   лог `Вы · crit (skill_code) 12`. Стоимость скилла не показана нигде.
5. **Звука нет вообще** (ни пакета, ни ассетов). VFX — только белый флеш.
   Цифры урона прибиты к долям экрана, не к спрайту. У `Monster` только
   `spriteIdle/spriteAttack` — нет hit/death.
6. **Старт — голый спиннер, финал — Material-иконка + строки.** Нет момента
   смерти моба, level-up не празднуется, `BattleCharacterSummary` не используется.
7. **Арена** — фон с экрана логина; отдельных боевых фонов нет.
8. **Устойчивость:** `BattleResumed` не диспатчится, нет `PopScope` (системный
   «назад» = висящая сессия до TTL), обрыв сокета в бою не обрабатывается.
9. **Глубины нет:** 2 скилла на класс, у мобов `castTimeSec: 0` → нечего
   телеграфить и не на что реагировать; интеррапт каста станом в движке есть,
   но игрок его никогда не увидит.

## Фазы

Порядок: P0 → P1 (текущий релиз), P4 → P2 → P3 → P5 (следующий). Фактически
P3 уехал вперёд P2: P2 упирается в ассеты, которых нет, а P3 их не ждёт.
Клиентская хореография строится на событиях, поэтому контракт чинится первым.
Перекладка экрана (P4) идёт раньше арены из P2 и раньше ленты намерений (P5):
и тени с плоскостью земли, и лента рисуются уже под новую композицию — иначе
работа делается дважды. P2 и P3 ждут ассетов, P4 не ждёт ничего.

Раскладки собраны прототипами, их можно открыть в браузере и сравнить вкладками:
[design/prototypes/](../../../design/prototypes/) — `battle-screen-current.html`
(реплика того, что есть сейчас) и `battle-screen-arena.html` (предложение).

## Баланс (пересекается с MVP-4)

- Дать каждому классу 3-й скилл с эффектом (воину — ABSORB, магу — DOT), чтобы
  в бою было решение, а не спам по кулдауну.
- Мобы: 1–2 телеграфируемых скилла с кастом (видимость очереди — P5); фаза «ярость» при HP < 30 %
  (визуально: красный тинт + событие `phase`?) — решить в MVP-4.

## Делегирование

- P0 — Opus (движок + контракт, риск регрессий; тесты обязательны).
- P1 — делегат (codex/GLM) по подпунктам «Читаемость», Opus — «Отзывчивость»
  (очередь событий, оптимистичная реакция) и ревью.
- P4 — перекладка механическая, но с вкусовыми решениями: делегат по прототипу,
  Opus — ревью композиции и открытый вопрос с эффектами игрока.
- P5 — Opus на контракт и данные ленты, делегат на вёрстку тайлов.
- P2/P3 — делегат после появления ассетов; Opus — ревью и аудио-сервис.
